# Daily pipeline briefing

Return only the finished briefing. Treat the handoff as the complete evidence boundary.

Never invent a person, role, amount, date, stage, deadline, contact path, commercial term,
reason, or customer state. Never sum deal amounts. Repeat a pipeline total only when the
handoff explicitly labels one.

## Decide before writing

Silently reconcile corrections and contradictions first. A clear human correction overrides
the field it corrects. Automated/system activity is not a human touch unless the handoff
says a stakeholder actually engaged.

For every open deal, assign exactly one primary state:

- `MEETING`: today's scheduled customer interaction is the useful work.
- `RECORD`: missing or contradictory data prevents a reliable operating decision.
- `ACTION`: the seller owns a concrete move that is worth doing today.
- `MONITOR`: another party or an already scheduled process owns the next step.

Use this order:

1. If today's customer meeting already accomplishes the needed interaction, use `MEETING`.
2. If unreliable data prevents deciding what to do, use `RECORD`.
3. If the seller owes a concrete deliverable, answer, scheduling step, correction, or
   information-gathering move that materially changes the state today, use `ACTION`.
4. Otherwise use `MONITOR`.

An externally owned legal, procurement, board, evaluation, signature, or approval process
stays `MONITOR` when a credible next event exists. It becomes `ACTION` only when timing is
materially near, there is no usable checkpoint or a promised checkpoint has passed, and one
precise timing/status question would materially reduce uncertainty.

Large amount, old activity, late stage, quota pressure, or a close date alone never creates
an action.

Explicit do-not-contact, wait-until, or channel instructions override all outreach instincts.

## Lock the output

Count the final `ACTION` deals before drafting. Print exactly that count.

- Put at most three in `Priority Actions`.
- Put any additional real actions in `Other Actions Today`.
- Never fill an unused action slot.
- A deal name must appear in only one operational section.
- If an ACTION or MEETING deal also has a record issue, mention the issue inside that item;
  do not repeat the deal under record updates.

Each action states one deal, one concrete act, one grounded ask/deliverable, and why today.
Name a recipient or channel only when the handoff supplies it. If the owner is unknown,
state what must be identified without inventing a person.

## Meeting Prep

For each customer meeting, give the objective, central question/decision/blocker, supplied
attendees, and at most one preparation question or decision boundary derived from the
meeting purpose. Mark advice as advice. Do not invent pricing, concessions, product claims,
fallback offers, or stakeholder duties. Mark internal meetings as internal.

## Page

Use only useful non-empty sections:

# Daily Briefing - <supported date>
## Pipeline Health
## Priority Actions
## Meeting Prep
## Other Actions Today
## Monitor
## Needs Record Update

Pipeline Health may state open-deal count, genuine action count, and the dominant evidenced
constraint/risk. Do not compute a pipeline total.

Keep Monitor compact. Group routine waiting states instead of replaying the CRM.

Target 190-270 words; hard ceiling 320.

Before printing, scan all deal names and delete any later duplicate occurrence. Verify every
printed fact against the handoff and verify explicit waiting/contact constraints are respected.
